# GridPulse database export

`gridpulse_dry_run.sql` is a PostgreSQL plain-text SQL dump of the local `gridpulse` database, including the TimescaleDB extension, schemas, hypertable/chunk data, and simulator telemetry. It was restored successfully into a disposable PostgreSQL 18.6 database for verification.

`gridpulse_schema.sql` is the schema-only PostgreSQL/TimescaleDB export. Use it as the structural reference for a new empty database; use the dry-run export when you also want the clearly labeled simulator test history and initial hierarchy rows.

The runtime schema also creates `grid_nodes` (`parent_node_id`, national/division/district/feeder tier, optional `distribution_weight`) and the `grid_node_readings` TimescaleDB hypertable. The SQL dump contains the national root plus eight division **topology labels only**. All division weights and readings are null/unmeasured; district substations and feeder clusters must be populated by the forthcoming authorized source-processing script. Regional estimates are disabled until the project supplies all eight weights summing to 100%.

## Data provenance

- The 48-hour hourly series was generated by the deterministic GridPulse simulator for an architecture dry run.
- It contains 20 virtual nodes and is labeled `source = 'simulator'`.
- It is **not PGCB data**, not real telemetry, and must not be presented as real grid history.
- The database currently has no rows in `national_grid_readings`; live PGCB data still requires an authorized source or history CSV.

## Restore

Install PostgreSQL with the compatible TimescaleDB extension, create an empty database, then execute the SQL dump while connected to that database:

```bash
createdb gridpulse_copy
psql -v ON_ERROR_STOP=1 -d gridpulse_copy -f database/gridpulse_dry_run.sql
```

This dump does not contain `DROP DATABASE` or `CREATE DATABASE` statements. Keep it as a development/test fixture; do not use the generated simulator rows as operational measurements.

## Backup format

PostgreSQL's physical data directory is machine-specific and is not included in this repository. Use the portable SQL exports in this directory to recreate the documented development/test database.
